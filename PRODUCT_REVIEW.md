# Ревью состояния продукта

Дата ревью: 2026-05-21.

## Общая оценка

Продукт находится в состоянии рабочего MVP: основной сценарий учителя уже собран от входа до PDF-экспорта, есть Docker-запуск, Postgres, API, хранение изображений и LLM-пайплайн. Для пилота и демонстрации продукт пригоден. Для промышленной эксплуатации нужно усилить надежность фоновой обработки, тесты, пользовательские сценарии вокруг истории заданий и эксплуатационные контуры.

## Что готово

- Docker Compose поднимает Postgres и backend, backend отдает собранный frontend.
- Есть авторизация по email/password из конфигурации и защищенные API-маршруты.
- Учитель может создать задание, загрузить одно изображение PNG/JPG/WEBP до 10 MB и запустить обработку.
- Backend валидирует тип и размер файла, сохраняет оригинал локально и отдает его через защищенный endpoint.
- Реализован четырехшаговый пайплайн: markdown исходника, параметры задания, допустимые вариации, финальный вариант.
- Есть mock-провайдер и интеграция с GigaChat, включая разные модели для финального шага.
- Frontend умеет опрашивать статус запуска, показывать исходное изображение и результаты шагов.
- На шагах 2 и 3 есть ручная правка, сохранение, продолжение и перегенерация.
- При успешной обработке финальный markdown рендерится в документ и скачивается в PDF.
- Есть миграции БД для заданий, изображений, запусков обработки и логов LLM-вызовов.

## Что нужно доделать

- Добавить автоматические тесты: сейчас в backend нет `*_test.go`, во frontend нет тестов компонентов или e2e.
- Добавить список/историю заданий, поиск, статусы и возврат к последнему запуску без ручной ссылки.
- Перенести фоновые LLM-шаги из goroutine в надежную очередь/worker: сейчас обработка может потеряться при рестарте процесса.
- Сделать восстановление незавершенных запусков после рестарта и явную модель статусов для зависших run.
- Усилить безопасность: постоянные пользователи/роли, хранение сессий вне памяти процесса, CSRF/rate limit, управление секретами.
- Согласовать поддержку WEBP: frontend и storage принимают WEBP, но GigaChat-провайдер его отклоняет.
- Добавить observability: структурные request-id в бизнес-логах, метрики длительности шагов, алерты ошибок LLM.
- Добавить аудит и просмотр raw/parsed LLM-ответов в админском режиме.
- Улучшить контроль качества LLM-ответов: явная валидация markdown/параметров/вариаций и человекочитаемые warnings.
- Добавить очистку старых файлов, версии изображений или явную замену с удалением предыдущего файла.
- Документировать production-конфигурацию, TLS, домен, бэкапы Postgres и storage.

## Вывод

Ближайшая цель: довести MVP до пилотного продукта. Минимальный набор для пилота: история заданий, очередь обработки, тесты ключевого API, согласованная поддержка форматов изображений, базовые логи/метрики и production-инструкция.
